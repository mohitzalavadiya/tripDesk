## 3. Required permission behavior

Implement and reconcile the following behavior across the entire app.

### Agency Owner

- The Agency Owner can open and use all ordinary pages belonging to their agency.
- The Agency Owner can manage page permissions for agency staff through the existing permissions-management interface.
- Every ordinary application page must have configurable permissions, rather than an unchangeable `ownerOnly` flag that prevents delegation.
- Do not let staff grant permissions to themselves or modify another user's permissions.
- Preserve the existing permission-management audit trail and reliable save/reload behavior.

### Agency Staff

Every application page must remain visible in the staff sidebar and corresponding mobile navigation, regardless of its assigned permissions.

Do not hide a page merely because the staff member lacks access.

- If View is granted, staff can view the permitted page and its authorized data.
- If View is denied, direct navigation must show the established restricted-access state. Protected data must not be fetched or exposed.
- If Add/Create is granted, staff can create the relevant records.
- If Edit/Update is granted, staff can modify the relevant records.
- If Delete is granted, staff can perform only the permitted deletion operations.
- If Export is supported and granted, staff can export the permitted data.
- If an action is not granted, disable or omit the corresponding action control using existing UI patterns and enforce the denial on the server.
- Add, Edit, and Delete should automatically require or enable View. If the current UI has this dependency, preserve it consistently.
- Permission changes must take effect without requiring a new account or an unrelated configuration change.

Do not implement permissions only in the UI. Direct URLs, APIs, server actions, and service-layer operations must enforce the same rules.

- Save and reload the exact persisted permissions.
- Avoid silently restoring owner-only defaults when reopening the modal.
- Preserve unsaved-change handling, loading states, error messages, and retry behavior.
- Support a large responsive layout without clipping controls or making lower pages inaccessible.

Define and verify the exact Page Access behavior. Turning it off must revoke that page's delegated actions. Turning it on must enable only the documented defaults; it must not silently grant unrelated sensitive capabilities. Individual actions must remain configurable.

Do not merely rename a label and claim the modal is fixed.

## 6. Security boundaries that must remain intact

Removing unnecessary owner-only restrictions must not compromise security.

Preserve:
- Agency tenant isolation. Always derive `agencyId` from authenticated server context, never from client-controlled input.
- Platform-owner-only platform administration and credential-protection controls.
- Subscription and SaaS-level operations that are outside ordinary agency delegation.
- Existing safeguards for payment verification, voiding, and other privileged financial operations unless the existing product specification explicitly authorizes delegation.
- Sensitive supplier costs, net rates, margins, payables, bank details, and internal financial data that staff are not authorized to see.
- Existing customer-data access controls, authentication checks, subscription/write-access rules, and audit logging.

However, do not use these safeguards as a reason to lock an entire ordinary page if the intended behavior is to allow safe delegated access.

Where a page combines operational and sensitive financial information, separate the permissions and redact unauthorized fields. Allow the staff member to perform permitted operational actions without exposing protected data.

Review the nested permission distinctions, including customer versus supplier payments. Do not merge distinct security domains into one broad permission.

For each remaining immutable owner-only restriction, document the exact protected operation, why delegation is unsafe or contrary to the product rules, and where it is enforced. No unexplained owner-only restrictions should remain on ordinary pages.
